OpenCL-OpenGL Interaction
-------------------------
OpenGL: "Open Graphics Library"
    Cross-platform API for visualization on the GPU
    Includes shader languages

OpenCL: "Open Computing Language"
    Language for SIMD-type parallel programming
    Simple C-like language for writing vectorized code to run on:
        Mulitple CPU cores
        GPUs
        Cell architectures
        etc.
    Better suited for computation than GLSL shaders
    Often better-suited for vectorized CPU code (SSE, AVX) than C/C++
    Basic concept:
        You have a single operation/program you want to run on thousands of
        different inputs
        You write a "Kernel" to implement that program, and launch thousands
        of (conceptually) concurrent instances, one per input

Contexts
    Both OpenGL and OpenCL have them
    OpenGL:
        Keep track of state, transformations, shader programs, memory buffers
        (vertex buffers, frame buffers, textures)
    OpenCL:
        Keep track of kernels, memory buffers

Typical program flow:
    Create OpenCL context on a device (gpu, cpu, ...)
    Compile OpenCL Kernels
    Allocate memory buffers in the context
    Copy intput data from CPU to the device's input buffers
    Run the kernel
    Copy output data form the devices's buffers back to the CPU 
    Post-process

But if we want to visualize the results, this is wasteful...
why can't we keep the data on the GPU?

Need OpenCL and OpenGL contexts to share data...

    Problems:
        Complicated geometry hard to mesh robustly

        Sometimes you don't even have a mesh (CSG)
